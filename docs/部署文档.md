# 部署文档

## 1. 架构总览

```text
访客浏览器
   │
   ├── HTTPS ── GitHub Pages（静态站点，main 分支根目录）
   │                └── CNAME: sunzhihaoai.top
   │
   ├── /admin/ ── Sveltia CMS（纯前端，浏览器内运行）
   │                └── OAuth ── Netlify Functions（token 交换）
   │                              └── GitHub API（读写仓库）
   │
   └── 留言 ── giscus ── GitHub Discussions
```

站点本身是纯静态文件，没有服务端、没有数据库。唯二的外部依赖是 OAuth 代理（仅后台登录用）与 giscus（仅留言板用）。

## 2. 部署到 GitHub Pages

### 2.1 前置条件

- GitHub 账号与一个仓库（当前为 `Sun-1025/Sun-1025.github.io`）
- 仓库为 Public（免费账号的 Pages 需要公开仓库）
- 本地已安装 Git

### 2.2 首次部署

```bash
git clone https://github.com/<owner>/<repo>.git
cd <repo>
# 把项目文件放到仓库根目录，保留 index.html、CNAME、assets 等
git add .
git commit -m "chore: 初始化站点"
git push origin main
```

### 2.3 开启 Pages

1. 仓库 `Settings → Pages`。
2. `Source` 选 `Deploy from a branch`。
3. 分支选 `main`，目录选 `/ (root)`，保存。
4. 等待首次构建，地址形如 `https://<owner>.github.io`。

### 2.4 绑定自定义域名

1. `Settings → Pages → Custom domain` 填 `sunzhihaoai.top`，保存。
2. 仓库根目录必须有 `CNAME` 文件，内容为域名本身（一行，不带协议、不带斜杠）：

```text
sunzhihaoai.top
```

3. 回到 Pages 设置勾选 `Enforce HTTPS`。证书签发通常几分钟，最长 24 小时。
4. 证书生效后，`http://` 与 `www` 都应 301 到 `https://sunzhihaoai.top`。

### 2.5 DNS 配置（阿里云）

在「云解析 DNS → 解析设置」中配置：

| 类型 | 主机记录 | 记录值 | TTL |
| --- | --- | --- | --- |
| A | `@` | `185.199.108.153` | 10 分钟 |
| A | `@` | `185.199.109.153` | 10 分钟 |
| A | `@` | `185.199.110.153` | 10 分钟 |
| A | `@` | `185.199.111.153` | 10 分钟 |
| CNAME | `www` | `sun-1025.github.io` | 10 分钟 |

注意两点：

- `www` 的 CNAME 目标是 `<owner>.github.io`，不是自定义域名，否则会循环解析。
- 若之前给 `www` 配过 A 记录，必须先删除，同一主机名不能同时存在 A 与 CNAME。

批量导入可用阿里云的「导入/导出 → 增量导入」，参考 `docs/deploy/dns-import.zone` 的格式；导入前把示例里的域名与 IP 换成自己的。

### 2.6 验证

```bash
# 解析
nslookup sunzhihaoai.top
nslookup www.sunzhihaoai.top

# 状态码与证书
curl -I https://sunzhihaoai.top
curl -I https://www.sunzhihaoai.top

# 关键文件
curl -I https://sunzhihaoai.top/index.html
curl -I https://sunzhihaoai.top/site.json
curl -I https://sunzhihaoai.top/sitemap.xml
curl -I https://sunzhihaoai.top/robots.txt
```

预期：主域 200，`www` 301，证书机构为 GitHub 签发的 Let's Encrypt 系证书，且 SAN 同时包含主域与 `www`。

## 3. 部署 OAuth 代理

后台登录需要一个能安全保存 `Client Secret` 的服务端。仓库内 `oauth-proxy/` 是 Netlify Functions 实现，也可移植到 Vercel、Cloudflare Workers。

### 3.1 创建 GitHub OAuth App

`GitHub → Settings → Developer settings → OAuth Apps → New OAuth App`：

| 字段 | 值 |
| --- | --- |
| Application name | `sunzhihao-cms-auth` |
| Homepage URL | `https://sunzhihaoai.top` |
| Authorization callback URL | `https://<代理域名>/api/callback` |

创建后记下 `Client ID`，生成 `Client Secret`（只显示一次）。

### 3.2 部署函数

```bash
cd oauth-proxy
npm install -g netlify-cli
netlify login
netlify init        # 关联或新建站点
netlify deploy --prod
```

在 Netlify 站点 `Site settings → Environment variables` 添加：

| 变量 | 值 |
| --- | --- |
| `GITHUB_CLIENT_ID` | OAuth App 的 Client ID |
| `GITHUB_CLIENT_SECRET` | OAuth App 的 Client Secret |

重新部署使变量生效。

### 3.3 验证代理

```bash
curl -I https://<代理域名>/auth
# 预期 302，Location 指向 github.com/login/oauth/authorize
```

然后打开 `/admin/` 完整走一遍登录。

### 3.4 换域名的检查清单

1. OAuth App 的 Homepage 与 Callback 改成新域名。
2. `admin/config.yml` 的 `base_url`、`site_url`、`display_url` 同步更新。
3. 仓库 `CNAME` 改成新域名。
4. DNS 增加新域名记录，旧域保留 301。

## 4. 本地预览

```bash
python -m http.server 8000
# 访问 http://localhost:8000
```

直接双击 `index.html` 也能看，但 `site.json` 会被 `file://` 的同源策略拦截，只显示内联兜底数据。需要验证真实数据时务必起本地服务。

本地打开 `/admin/` 时，CMS 仍指向线上仓库与线上代理，提交会直接改线上内容，调试请用测试分支或在 `config.yml` 临时改 `branch`。

## 5. 内网部署方案（规划）

外网访问受 GitHub Pages 跨境节点影响，晚高峰可能卡顿。规划中的内网方案：

```text
内网服务器
  ├── Nginx（静态托管 + gzip/brotli + 长缓存）
  ├── 定时任务（每 5 分钟 git pull 同步 main）
  └── 可选：Docker Compose 一键起站
```

Nginx 最小配置：

```nginx
server {
  listen 80;
  server_name portfolio.lan;
  root /var/www/portfolio;
  index index.html;

  gzip on;
  gzip_types text/css application/javascript application/json image/svg+xml;

  location /assets/ {
    expires 30d;
    add_header Cache-Control "public, immutable";
  }

  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

内网与公网共用同一仓库：内网只读同步，公网继续由 Pages 发布；后台仍走公网，避免内网暴露写权限。

## 6. Gitee 镜像部署

Gitee 适合作为国内访问的镜像与代码备份，不建议作为唯一发布源。

- 仓库设为公开后，Gitee Pages 需在「服务 → Gitee Pages」中手动开启并等待审核。
- Gitee Pages 的自定义域名需要额外绑定与实名认证，且不自动签发免费 HTTPS。
- 若仅做镜像，保持与 GitHub 同一份文件即可，`CNAME` 文件对 Gitee Pages 无副作用。

同步方式二选一：

```bash
# 方式一：加一个 remote，手动推两边
git remote add gitee https://gitee.com/<user>/<repo>.git
git push gitee main

# 方式二：GitHub Actions 自动镜像（需在 Gitee 生成私人令牌）
```

## 7. 备份与迁移

- 代码与内容都在 Git 历史里，克隆即完整备份。
- 媒体文件在仓库内，随 clone 一起拿到；`assets/_raw/` 为本地原始素材，不在仓库内，需要单独备份。
- 迁移到新账号：新建仓库 → `git remote set-url` → 推送 → 重开 Pages → 改 DNS → 重建 OAuth App。

## 8. 排错速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Pages 404 | 分支/目录选错，或缺 `index.html` | 检查 Pages 设置与仓库根目录 |
| 自定义域名被重置 | `CNAME` 文件丢失 | 补回 `CNAME` 并重新保存设置 |
| 证书一直 `unapproved` | DNS 未生效或 CAA 限制 | 等待解析生效，检查 CAA 是否允许 Let's Encrypt |
| `www` 显示不安全 | 证书未覆盖 `www` | 重新保存自定义域名，等待证书重签 |
| 后台 401 | token 过期 | 重新登录 |
| `/auth` 404 | 函数未部署或路由不符 | 检查 `netlify.toml` 与部署日志 |
| 留言板空白 | giscus 未安装或仓库未开 Discussions | 安装 giscus App，开启 Discussions |
| 页面样式错乱 | CDN 字体被拦截 | 检查网络与拦截插件，或改本地字体 |
