# 内网部署与访问加速

> 目标：局域网内设备直连本机 Node 服务，避免跨洋/GitHub Pages 延迟；同时保留 GitHub Pages 外网版本。

> 本文命令默认使用 PowerShell 7（`pwsh`）。如果你的机器只有 Windows PowerShell 5.1，把 `pwsh` 换成 `powershell` 即可。

## 1. 架构

```
局域网设备 ──HTTP──> Windows 本机 Node :8080 ──> data/site.json
外网访客   ──HTTPS──> GitHub Pages / Cloudflare Pages（静态导出 dist/）
```

本机服务是“内容源 + 后台”；外网 Pages 是“只读镜像”。后台改完内容后，本地立即生效；外网需要手动导出并推送。

## 2. 内网部署步骤（Windows）

### 2.1 环境

- Node.js 18 或更高（`node -v` 确认）
- 项目目录：`C:\Users\sun\OneDrive\Desktop\实习\portfolio-v2`
- 默认端口 `8080`；可在 `.env` 改 `PORT`

首次部署：

```powershell
cd C:\Users\sun\OneDrive\Desktop\实习\portfolio-v2
Copy-Item .env.example .env
notepad .env       # 修改 ADMIN_PASSWORD、JWT_SECRET（可选）
npm install
npm run init -- admin 你的新密码
npm start
```

看到日志里的“局域网访问：http://172.29.30.15:8080”即启动成功（IP 以实际为准）。

### 2.2 查本机内网 IP

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object InterfaceAlias, IPAddress
```

假设结果是 `172.29.30.15`，则局域网访问地址为：

- 前台：`http://172.29.30.15:8080/`
- 后台：`http://172.29.30.15:8080/admin`
- 经典版：`http://172.29.30.15:8080/classic/`

### 2.3 放行 Windows 防火墙（需管理员 PowerShell）

```powershell
New-NetFirewallRule -DisplayName "PortfolioV2 8080" `
  -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

如果只在同一台电脑访问，可跳过这一步。

### 2.4 一键启动 / 停止

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File deploy\start-server.ps1
pwsh -NoProfile -ExecutionPolicy Bypass -File deploy\stop-server.ps1
```

也可以双击 `deploy\start-server.cmd`。

### 2.5 开机/登录自启

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File deploy\install-autostart.ps1
```

脚本会注册计划任务 `PortfolioV2-Server`，当前用户登录 Windows 时自动启动。
取消自启：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File deploy\uninstall-autostart.ps1
```

> 说明：计划任务在“用户登录后”启动，适合个人电脑。若希望开机即启动（无需登录），需要用 NSSM 把 Node 注册为 Windows 服务，或改用 Windows Server + IIS/Nginx。

### 2.6 局域网设备访问

1. 手机/另一台电脑连接同一个 Wi-Fi 或同一交换机。
2. 浏览器打开 `http://172.29.30.15:8080/`。
3. 如果打不开：检查防火墙、路由器“AP 隔离/客户端隔离”、IP 是否变化。
4. 建议在路由器给这台电脑绑定固定 DHCP 地址，避免 IP 变化后入口失效。

## 3. 外网版本保留与同步

### 3.1 GitHub Pages（保留现有外网入口）

```powershell
npm run export
# 如果仓库是项目子路径，例如 https://github.com/Sun-1025/portfolio：
npm run export -- --base=/portfolio/
```

把 `dist/` 里的内容推到 Pages 分支（常见是 `gh-pages`），或用 GitHub Actions 构建。`dist` 不含后台、不含 API，前台自动回退到 `data/site.json`，SSE 自动跳过。

现有域名 `sunzhihaoai.top` 继续指到 Pages 即可；后台只在本地/内网使用。

### 3.2 Cloudflare Pages（外网加速备选）

- 连接 Git 仓库
- Build command：`npm run export`
- Output directory：`dist`
- Node 版本：18+
- 自定义域名：在 Cloudflare 里把 `sunzhihaoai.top` 的 DNS 指过去

Cloudflare 的边缘缓存对静态资源更友好；后台仍然只在本机运行。

### 3.3 性能优化清单

| 项 | 现状 / 做法 |
|---|---|
| 传输压缩 | 服务端已启用 `compression` |
| 静态缓存 | `/assets` 30 天 immutable；`/uploads` 7 天 |
| 图片 | 统一 WebP；静态导出时 sharp 二次压缩，最长边 1600 |
| JS/CSS | 静态导出用 terser / clean-css 压缩 |
| 懒加载 | 图片 `loading="lazy"`；项目图按需加载 |
| 后台隔离 | `dist` 不含 admin.css / admin.js，减小外网包体 |
| 动画性能 | 只对 `transform` / `opacity` 做动画，尊重 `prefers-reduced-motion` |

## 4. 可选内网穿透

### 4.1 Tailscale（最省事，推荐）

1. 本机与手机都安装 Tailscale，登录同一账号。
2. 本机执行 `tailscale ip -4`，得到 `100.x.x.x`。
3. 外网访问 `http://100.x.x.x:8080/`。
4. 优点：不用开路由器端口，流量加密；缺点：每台访问设备都要装 Tailscale。

### 4.2 frp（需要一台有公网 IP 的服务器）

- 公网服务器跑 `frps`，本机跑 `frpc`，把本机 `8080` 映射到公网端口。
- 只映射前台，后台 `/admin` 建议不要直接暴露；如必须暴露，加 Nginx Basic Auth + HTTPS。
- frp 配置涉及端口、token、防火墙，按实际服务器调整。

### 4.3 Cloudflare Tunnel

- 本机安装 `cloudflared`，执行 `cloudflared tunnel --url http://127.0.0.1:8080` 可快速得到一个临时公网地址。
- 长期使用建议创建 Named Tunnel + Access 策略，只允许自己的邮箱访问 `/admin`。

> 安全底线：不要把未改密码的后台直接暴露到公网；不要把 `data/.jwt-secret`、`data/users.json` 上传到公开仓库。

## 5. 可选 Nginx 反代

参考 `deploy/nginx.conf.example`。关键点：

- `client_max_body_size 10m` 允许图片上传
- `proxy_buffering off` 保证 SSE 实时刷新
- `proxy_read_timeout 3600s` 避免长连接被切断
