# 功能介绍

按模块说明站点做了什么、为什么这样做，以及二次开发时该看哪一段代码。

## 1. 首屏场景

场景由 13 张同机位渲染图组成，覆盖正面、左、右、上以及 30°/60° 斜角。所有图片按视口 `cover` 铺满，暗态下叠加一层暗色遮罩。

- 相关代码：`index.html` 场景层样式约在第 200 行，场景逻辑在 `gaze()` 自执行函数。
- 关键常量：`MAX_X = 22`、`MAX_Y = 14` 控制位移幅度，`LERP_POS = 0.3` 控制跟随阻尼，`STEP_MS = 260` 控制每次换向的间隔。
- 朝向映射：`DIRS12` 把 12 个方位压缩成 9 张可用图，没有对应图的角度复用邻近帧，避免出现空帧。
- 头部遮罩：按 2048×1152 的设计基准等比换算，窗口尺寸变化时重新计算，保证人物头部不被拉变形。

**为什么用多图切帧而不是视频**：视频首帧解码慢、移动端自动播放受限、循环接缝明显。切帧方案首屏只加载正面一张，其余按需解码，且能随时暂停降级。

## 2. 分支舞台与连线

六个节点用绝对定位摆在舞台左右两列，三行分布：

```js
const rows = [0.26, 0.50, 0.74];
```

每个节点带独立的 `dx`、`dy`、`rot`，形成轻微错位与倾斜，避免像表格一样对齐。

`layout()` 负责三件事：

1. 计算节点中心坐标；
2. 求「舞台中心椭圆」与「节点连线」的交点，让曲线从人物轮廓边缘出发，而不是从画面正中穿出；
3. 生成二次贝塞尔路径，用 `Q` 控制点制造手绘弧度。

窗口缩放时防抖重排；宽度 ≤ 760 px 时清空 SVG，改用纵向堆叠布局。

## 3. 面板系统

面板是右侧滑出的整屏抽屉，带背景模糊与边框高光。三个面板：分支列表、案例详情、留言。

- 打开时锁定页面滚动，关闭时恢复。
- 支不支持多面板叠加？不支持。`openPanel()` 会先关闭已有面板，避免层级打架。
- 详情面板顶部有一条阅读进度条，按 `scrollTop / (scrollHeight - clientHeight)` 计算；面板切换时重置为 0。

详情内容由 `DETAILS` 对象提供，结构为：

```js
{
  kicker: '项目 · 2025',
  title: '图书管理系统',
  desc: '一句描述',
  images: ['assets/library-shot.webp'],
  tags: ['Python', 'SQL Server'],
  sections: [{ h: '背景', p: '...' }],
  result: '结果句'
}
```

配图轮播用 `setInterval` 自动切换，关闭面板时清除定时器，防止后台空转。

## 4. 视线与朝向的滞回

鼠标位置换算成归一化坐标后，按角度落到 12 个扇区之一。为避免鼠标停在分界线时来回闪，加入了滞回：只有跨过扇区中心一定角度才切换，切换后再经过 `STEP_MS` 才允许下一次。

`prefers-reduced-motion: reduce` 时步进间隔归零，直接跳帧，不做过渡。

## 5. 主题

深色是默认。浅色主题不是简单反色，而是重算了一套令牌：

| 令牌 | 深色 | 浅色 |
| --- | --- | --- |
| `--bg` | `#131209` | 米白 |
| `--surface` | `#1f1f1f` | 浅灰白 |
| `--ink` | `#ece7db` | 深墨 |
| `--accent` | `#cdd96b` | 同色系压暗 |

切换时给 `<html>` 加 `data-theme="light"`，并把选择写入 `localStorage['theme']`。首次访问跟随系统 `prefers-color-scheme`，之后以用户选择为准。

## 6. 留言板

giscus 通过 GitHub Discussions 存储评论，仓库需满足：公开、已安装 giscus App、已开启 Discussions、建好对应分类。

加载策略是「点击才加载」：初始只渲染一个占位容器，点击留言按钮时才注入 `<script>`，避免第三方脚本拖慢首屏。主题跟随站点，深色用 `transparent_dark`。

配置项集中在 `loadGiscus()`：

```js
repo: 'Sun-1025/Sun-1025.github.io',
repoId: 'R_kgDOV1etUw',
category: 'Announcements',
categoryId: 'DIC_kwDOV1etU84DLtON',
mapping: 'pathname',
```

## 7. 数据层

优先级：`site.json` > 内联 `DATA`。

```js
fetch('site.json', { cache: 'no-store' })
  .then(r => r.json())
  .then(d => { DATA = d; render(); })
  .catch(() => { /* 保留内联数据 */ });
```

`no-store` 是为了让后台发布后立即生效，代价是每次访问都发一次约 27 KB 的请求。若后续内容趋于稳定，可改成 `cache: 'default'` 并给文件名加版本号。

## 8. SEO 与可访问性

- `canonical`、`og:*`、`twitter:*` 全部指向主域，避免 `www` 重复收录。
- JSON-LD 用 `Person` 类型描述姓名、学校、方向，便于搜索引擎生成知识卡片。
- 节点是 `<button>`，带 `aria-label`；面板有 `role="dialog"` 与焦点管理；装饰图 `alt=""`。
- 主题色 `theme-color` 随深浅模式不改，保持品牌一致。

## 9. 性能取舍

| 项 | 现状 | 可优化方向 |
| --- | --- | --- |
| 首屏图 | 正面 WebP 约 213 KB | 加 `fetchpriority="high"`，其余 `loading="lazy"` |
| 场景全集 | 约 3 MB | 按方向懒加载，进入视口再解码 |
| 字体 | 思源黑体 + Manrope，CDN 加载 | 子集化或本地托管 |
| JS | 单文件约 40 KB | 无需拆分，压缩后可再降 |
| 缓存 | 静态资源无版本参数 | 给 `assets/*` 加 hash 或长缓存头 |

## 10. 扩展位置

后续加「在线工具」时，建议新增 `tools/` 目录与独立入口页，复用同一套设计令牌：

- 颜色、圆角、缓动：`index.html` 顶部 `:root`
- 玻璃卡片：`.panel`、`.talk` 的 `backdrop-filter` 写法
- 按钮与焦点态：`.nav button`、`.node`
- 数据：新增 `tools.json`，与 `site.json` 并列，后台加一个 collection 即可
