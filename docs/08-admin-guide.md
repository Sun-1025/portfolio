# 后台使用手册（不含密码）

> 地址：`http://localhost:8080/admin`
> 前提：本机 Node 服务在运行。GitHub Pages 是纯静态站点，不提供后台与 API。
> 账号与密码：只在本机 `.env` 或后台“系统 → 账号”中维护。仓库与本文档不记录明文密码。

## 1. 首次启动

```powershell
npm install
copy .env.example .env
npm start
```

首次启动会生成本机账号文件与 JWT 密钥；它们都在 `.gitignore` 里。不要把它们复制到 `public/` 或提交到 Git。

重置管理员账号：

```powershell
node scripts/init-admin.js admin "至少8位的新密码"
```

重置后重启服务或重新登录。命令中的密码可能进入 shell 历史；生产环境建议改用后台“账号设置”，并清理历史。

## 2. 后台长什么样

打开 `/admin` 是一屏内容卡片，不是 JSON 输入框：

- 左侧按类型分栏：项目、兴趣相册、工具、时间线、校园照片、联系方式、导航、分支、公告。
- 站点信息、首屏、关于、AI 助手、设置这 5 类各一条，点开直接改。
- 每条卡有封面、标题、摘要、更新时间和状态徽章。
- 状态：公开（绿）、私密（黄）、草稿（灰）、回收站（红）。
- 卡片动作：设为私密/公开、存草稿、编辑、删除；回收站里可恢复或彻底删除。

## 3. 三种可见性

编辑抽屉顶部有“访客可见性”：

| 选项 | 行为 |
|---|---|
| 公开 | 接口返回真实内容，静态导出写入 `dist` |
| 私密 | 公开接口返回占位，静态导出不写真实内容 |
| 草稿 | 公开接口不返回，导出不写；后台仍可编辑 |

私密内容可以生成 10 分钟预览令牌，在本机预览；不要把预览令牌发给外部。

## 4. 新增项目

1. 左侧选“项目案例”。
2. 点“新增案例”。
3. 填 `id`（唯一，用于 `#/work/<id>`）、标题、摘要、分类、封面、图片、正文小节、外链。
4. 设为公开或草稿，保存。
5. 前台会自动刷新；如果没刷新，检查 SSE 或手动刷新页面。

分类建议：

- `project`：个人项目
- `internship`：实习
- `campus`：校园/公益
- `hobby`：兴趣

## 5. 新增工具

1. 在 `public/tools/` 写一个模块，导出 `render(root, ctx)`。
2. 左侧“工具”新增条目，填 `id`、名称、描述、分类、`module`、图标、排序。
3. `module` 必须与文件名一致，例如 `converter.js`。
4. 保存后访问 `#/tools/<id>`。

工具逻辑应尽量在浏览器本地完成；不要默认把用户文件上传服务端。

## 6. 改导航和联系方式

- 导航：左侧“导航”，控制显示/隐藏、顺序、标签。
- 分支：左侧“分支”，控制 SPA 路由是否允许访问。
- 联系方式：左侧“联系方式”，每条有 `visible` 和 `status`；不想公开就设为私密。

站点页脚、首屏文案、关于页分别走“站点信息”“首屏”“关于”三个单条内容。

## 7. 媒体与备份

- 媒体库只显示已上传的公开图片；上传有格式和大小限制。
- 保存内容会自动备份到 `data/backups/`，最多保留 30 份。
- 备份目录不进仓库，也不进 `dist`。
- 需要还原时，从备份 JSON 里复制对应条目，或让管理员在后台恢复。

## 8. 发布上线

1. 改完内容并保存。
2. 顶栏点“发布上线”。
3. 后台会构建 `dist/` 并推送 GitHub Pages。
4. 到线上检查首页、项目页、工具页和图片。

注意：发布脚本需要本机 GitHub 凭据；没有凭据时会在后台显示失败日志，不会伪装成功。

## 9. 安全习惯

- 不要在后台昵称、简介、公告里写密码或 token。
- 不要把 `/admin` 暴露到公网无鉴权地址。
- 离开电脑前退出后台；公用机器不要保存凭据。
- 发现密码可能泄露，立即在“系统 → 账号”改密码，并检查 `docs/`、issue、聊天记录。
- 不把 `data/users.json`、`data/.jwt-secret`、`private/` 发给任何人。

## 10. 常见问题

**打不开 `/admin`？**  
确认 `npm start` 正在运行；GitHub Pages 没有后台。

**登录后马上退出？**  
检查浏览器是否禁用 Cookie、系统时间是否准确、`SESSION_HOURS` 是否太短。

**保存后前台没变？**  
先刷新页面；再检查 `/api/events` 是否连接；静态站需要重新构建。

**发布失败？**  
检查本机 GitHub 凭据、网络、仓库权限；后台日志会显示失败原因。

**内容里有私密信息怎么办？**  
在后台把条目设为私密，重新构建；确认 `dist/data/site.json` 中没有真实值。
