本手册面向两类使用者：浏览站点的访客，以及需要更新内容维护者。维护者只需会改文字、会上传图片，不需要懂代码。

## 一、访客操作

### 页面结构

首页是一张全屏场景，左右各三条分支节点：

| 编号 | 节点 | 位置 | 内容 |
| --- | --- | --- | --- |
| 01 | 个人简介 | 左上 | 自我介绍、基本信息、技术能力、技能栈、理念、未来方向 |
| 02 | 校园经历 | 右上 | 学生岗位与赛事、宣传相关经历 |
| 03 | 项目经历 | 左中 | 图书管理系统、语音监测、公益课等 |
| 04 | 实习经历 | 右中 | 技术开发实习 |
| 05 | 兴趣爱好 | 左下 | 羽毛球、骑行、游戏、记账 |
| 06 | 其他方向 | 右下 | 联系方式、关于本站、后续方向 |

### 交互一览

| 操作 | 结果 |
| --- | --- |
| 移动鼠标 | 场景随视线方向切换角度，人物头部与画面产生视差 |
| 单击分支节点 | 打开对应面板，节点与连线高亮 |
| 面板内滚动 | 顶部阅读进度条同步 |
| 点击案例卡片 | 打开详情页，含配图、标签、小节正文与外链 |
| 双击场景空白处 | 弹出问候气泡 |
| 按 `Esc` | 关闭详情 → 关闭面板 → 关闭气泡 |
| 点击右下角留言按钮 | 展开 giscus 留言板 |
| 点击顶部主题按钮 | 深色 / 浅色切换，刷新后保持 |

移动端会自动折叠为纵向布局，隐藏连线与部分装饰，交互保持一致。

## 二、内容维护的三种方式

### 方式 A：可视化后台（推荐）

适合日常改文案、加案例、换图。

1. 打开 `https://sunzhihaoai.top/admin/`。
2. 用 GitHub 账号登录并授权。
3. 在 `Site` 集合中编辑字段。
4. 点 `Publish` 提交，约 1 分钟后线上生效。

字段逐项说明见 [后台管理.md](后台管理.md)。

### 方式 B：直接编辑 `site.json`

适合批量替换或本地备份恢复。文件是标准 JSON，顶层五个键：

```json
{
  "about": { ... },
  "cases": [ ... ],
  "contacts": [ ... ],
  "directions": [ ... ],
  "note": "..."
}
```

改完保存，本地起服务预览（`python -m http.server 8000`），确认无误后提交到仓库。

注意：JSON 不支持注释，字符串里的双引号必须转义为 `\"`，最后一项后面不能多逗号。

### 方式 C：改 `index.html` 内联数据

`index.html` 里有一份 `let DATA = { ... }` 兜底数据。它只在 `site.json` 读取失败时生效，正常访问时会被远程数据覆盖。仅在「离线单文件交付」场景下修改它。

## 三、内容字段速查

### `about`：个人简介

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `highlight` | 字符串 | 面板顶部大字，支持行内 `<em>` 强调 |
| `lines` | 字符串数组 | 正文段落，一段一项 |
| `facts` | 对象数组 | 基本信息，`k` 标签、`v` 值、`d` 可选详情键 |
| `abilities` | 对象数组 | 技术能力，`t` 标题、`d` 正文 |
| `skills` | 对象数组 | 技能栈，`n` 名称、`d` 可选详情键、`hot` 可选高亮 |
| `belief.lines` | 字符串数组 | 个人理念段落 |
| `belief.quote` | 字符串 | 理念金句 |
| `future` | 对象数组 | 未来方向，`t` 阶段、`d` 说明 |

`facts` 与 `skills` 里的 `d` 是「详情键」，与 `index.html` 中 `DETAILS` 对象的键对应。点击带 `›` 的条目会弹出补充说明；没有对应键时留空即可，条目不会出现箭头。

### `cases`：案例卡片

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | 字符串 | 唯一键，如 `case-lib`，**不要改**，改了会丢详情关联 |
| `cat` | 枚举 | `internship` / `project` / `campus` / `hobby` |
| `num` | 字符串 | 卡片编号，如 `01` |
| `title` | 字符串 | 标题 |
| `org` | 字符串 | 单位或归属 |
| `period` | 字符串 | 时间，如 `2025.09 — 2025.12` |
| `role` | 字符串 | 角色 |
| `summary` | 字符串 | 一句摘要 |
| `tags` | 字符串数组 | 标签 |
| `images` | 字符串数组 | 图片路径，如 `assets/library-shot.webp` |
| `links` | 对象数组 | 外链，`text` 文本、`url` 地址 |
| `sections` | 对象数组 | 详情小节，`h` 小标题、`p` 正文 |
| `result` | 字符串 | 结果句，显示在详情底部 |

`cat` 决定卡片出现在哪条分支：`campus` → 校园经历，`project` → 项目经历，`internship` → 实习经历，`hobby` → 兴趣爱好。

### `contacts`：联系方式

| 字段 | 说明 |
| --- | --- |
| `label` | 类型，如「邮箱」「Gitee」 |
| `value` | 显示值 |
| `url` | 跳转地址，`mailto:` 或 `https://`，留空则不可点 |

### `directions` 与 `note`

- `directions`：关于本站页的方向列表，`t` 方向、`d` 说明。
- `note`：关于这个网站的一段说明。

## 四、常见编辑场景

### 改一句自我介绍

后台 → `Site` → `个人简介` → `正文段落`，找到对应段落直接改。段落是一条一项，不要在一项里塞多个自然段。

### 新增一个项目案例

1. 后台 → `案例卡片` → `添加`。
2. `唯一键` 填 `case-xxx`（英文小写、短横线连接，不与现有重复）。
3. `分类` 选「项目经历」。
4. 依次填标题、时间、角色、摘要、标签。
5. `详情正文小节` 按「小标题 + 正文」成对添加。
6. 需要配图时先上传到媒体库，再把路径填进 `图片路径`。
7. 发布。

### 换首页场景图

1. 准备同尺寸 WebP（建议宽度 2048 px，单张控制在 300 KB 内）。
2. 上传到 `assets/`，文件名沿用 `scene-front.webp` 等既有命名，直接覆盖。
3. 因为文件路径没变，无需改代码，发布后即生效。

### 改联系方式

后台 → `联系方式`，改 `value` 与 `url`。邮箱记得保留 `mailto:` 前缀。

### 调整分支标题或顺序

节点标题与位置写在 `index.html` 的 `NODES` 数组里（`label`、`side`、`row`、`dx`、`dy`、`rot`），这部分不在后台字段内，需要改代码。

## 五、文案与排版约定

- **段落颗粒度**：`lines`、`belief.lines` 一项就是一段，靠段间距分隔，不要在字符串里写 `\n\n`。
- **行内标签**：字段按 HTML 渲染，可用 `<em>`、`<strong>`、`<br>`；不要插入 `<script>`、`<style>` 或外部嵌入代码。
- **长度控制**：简介正文单段建议 60–120 字；案例摘单一句话，不超过 40 字；小节正文 80–200 字。
- **标点**：中文内容用全角标点；中英文之间留一个空格；数字与单位之间留空格（如 `3.83 / 5.0`）。
- **链接**：外链一律带 `https://`，站内路径用相对路径且不带开头斜杠。
- **图片**：优先 WebP；配图宽度不超过 1600 px；上传前压缩到 300 KB 以内。

## 六、常见问题

**改了内容，线上没变？**

Pages 重建有 1–2 分钟延迟。先看仓库提交记录里有没有新 commit；有提交仍不变时，强制刷新（`Ctrl + F5`）或加 `?v=时间戳` 访问。

**后台登录后一片空白？**

多为浏览器扩展拦截了 CMS 的脚本请求。换无痕窗口或关闭拦截插件再试；也可能是 token 过期，退出重登。

**留言板加载失败，控制台报 `ERR_CONTENT_DECODING_FAILED`？**

AdGuard 等拦截器破坏了 `giscus.app` 的响应，把本站与 `giscus.app` 加入白名单。

**图片上传后不显示？**

检查路径是否为 `assets/uploads/文件名`，大小写要与实际文件一致；文件名避免中文与空格。

**误删了内容怎么办？**

在 GitHub 仓库的提交历史里找到上一次正确的 `site.json`，用后台重新粘贴，或本地回滚后重新发布。
