# 扩展开发指南

> 目标：不改核心代码就能加工具、加项目、加分支；确需新页面时按约定扩展。

## 1. 数据驱动范围

`data/site.json` 是唯一内容源，结构如下：

```json
{
  "site": {},
  "nav": [],
  "branches": [],
  "home": {},
  "work": { "cases": [] },
  "tools": { "items": [] },
  "notices": [],
  "settings": {}
}
```

后台保存时会校验 `site / nav / home / work / tools` 五个字段；`branches`、`notices`、`settings` 缺失也能工作，但建议保留。

## 2. 新增一个在线工具（推荐流程）

### 2.1 写模块

在 `public/tools/` 新建 `example.js`：

```js
export async function render(root, ctx) {
  root.innerHTML = `
    <div class="field">
      <label for="demoInput">输入</label>
      <textarea class="textarea" id="demoInput"></textarea>
    </div>
    <div class="tool-row">
      <button class="mini-btn" type="button" id="demoRun">运行</button>
    </div>
    <p class="hint" id="demoOut"></p>`;

  const input = root.querySelector('#demoInput');
  const out = root.querySelector('#demoOut');
  root.querySelector('#demoRun').addEventListener('click', () => {
    out.textContent = input.value.trim() || '（空）';
    ctx.toast('已处理');
  });
}
```

约定：

- 必须导出 `render(root, ctx)`，可以是 async。
- `root` 是工具面板容器，直接写 DOM。
- `ctx.toast` 用于轻提示；`ctx.item` 是当前工具配置。
- 纯前端计算，不请求后端；需要上传/保存才调用 API 并处理登录态。
- 不引入大型依赖；优先原生 JS。

### 2.2 注册到工具列表

后台「工具管理」新增一行，或直接编辑 `data/site.json`：

```json
{
  "id": "example",
  "name": "示例工具",
  "desc": "一句话说明",
  "category": "convert",
  "module": "example.js",
  "icon": "EX",
  "enabled": true,
  "order": 5
}
```

`category` 目前支持 `convert`（转换）与 `query`（查询）。`module` 必须与文件名一致。

### 2.3 访问

前台地址：`#/tools/example`。不需要改 `app.js`，动态 import 会按 `module` 加载。

### 2.4 关闭 / 排序

后台取消「启用」后，工具列表和详情都会隐藏；改 `order` 控制卡片顺序。

## 3. 新增项目案例

后台「项目案例」→「新增案例」：

- `id` 唯一，用于详情链接 `#/work/<id>`。
- `category` 支持 `project / internship / campus / hobby`。
- `images` 一行一个地址。
- `sections` 是正文小节，`links` 是外部链接。

无需改代码；保存后前台自动刷新。

## 4. 新增导航项 / 分支

### 4.1 只加导航入口

后台「导航与分支」→ 新增导航项：

- 站内路由：`type=route`，`target=home / work / tools`。
- 静态页/外链：`type=link`，`target=/classic/` 或完整 URL。
- `order` 越小越靠前，`visible` 控制显示。

### 4.2 新增一个真正的新分支页面

`branches` 只是元数据，不会自动生成页面。完整做法：

1. 在 `public/` 下新建页面，例如 `public/lab/index.html`。
2. 在 `server.js` 增加路由：

```js
app.get('/lab/', (req, res) => sendFile(res, path.join(PUBLIC, 'lab', 'index.html')));
```

3. 后台新增分支：`id=lab`、`type=custom`、`visible=true`。
4. 后台新增导航：`type=link`、`target=/lab/`。
5. 如果希望它成为 SPA 内部路由（而不是独立页面），在 `app.js` 的 `parseRoute()` 与 `render()` 增加分支；否则用独立静态页更简单。

> 分支的 `visible` 对 SPA 路由生效；独立静态页需要在页面自身或 Nginx 层做开关。

## 5. 修改首页模块

首页由 `app.js` 的 `renderHome()` 组合：

- Hero：`home.hero`
- 数据条：`home.stats`
- 公告：`notices`
- 关于：`home.about`
- 项目：`home.work` 引用 `work.cases`
- 技能：`home.about.skills`
- 经历：`home.experience`（若数据结构存在）
- 联系：`home.contacts`

新增字段时：

1. 先在 `data/site.json` 加默认值；
2. 在 `renderHome()` 读取并渲染；
3. 在后台 `viewHome()` 加对应表单；
4. 保存校验若要求新字段，更新 `src/routes/content.js` 的 required 列表。

## 6. API 一览

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/health` | 否 | 健康检查 |
| GET | `/api/content` | 否 | 读取整站内容 |
| PUT | `/api/content` | 是 | 保存整站内容 |
| GET | `/data/site.json` | 否 | 静态/经典版数据 |
| POST | `/api/auth/login` | 否 | 登录 |
| POST | `/api/auth/logout` | 是 | 退出 |
| GET | `/api/auth/me` | 是 | 当前会话 + `expiresAt` |
| POST | `/api/auth/password` | 是 | 修改密码 |
| POST | `/api/admin/upload` | 是 | 上传图片（字段名 `file`） |
| GET | `/api/admin/media` | 是 | 媒体列表 |
| DELETE | `/api/admin/media/:name` | 是 | 删除 uploads 图片 |
| GET | `/api/backups` | 是 | 备份列表 |
| POST | `/api/backups/:name/restore` | 是 | 恢复备份 |
| GET | `/api/events` | 否 | SSE 内容更新 |

鉴权使用 HttpOnly Cookie `pf_token`，前端请求带 `credentials: 'same-origin'`。

## 7. 主题与样式

- 前台样式：`public/assets/css/app.css`
- 后台样式：`public/assets/css/admin.css`
- 颜色通过 CSS 变量集中管理：`--ink`、`--paper`、`--accent`、`--line` 等。
- 动效只使用 `transform` / `opacity`；新增动画时保留 `prefers-reduced-motion` 分支。
- 新版主站是原生 CSS，不引入 Tailwind 运行时；如果后续要上 Tailwind，建议只在构建期生成 CSS，不要挂 CDN 运行时。

## 8. 静态导出注意事项

`npm run export` 会：

- 复制 `public/index.html`、`assets`、`tools`、`classic`、`data/site.json`、`uploads`；
- 删除 `admin.css` / `admin.js`；
- 压缩 CSS/JS/WebP；
- 生成 `.nojekyll` 与 `404.html`；
- 支持 `--base=/repo/` 子路径改写。

新增页面若也要进静态包，需要同步修改 `scripts/export-static.js` 的复制列表。

## 9. 代码风格

- 后端：`'use strict'`、小函数、错误统一走 `next(err)` 或 JSON。
- 前端：模块化、`esc()` 转义用户内容、避免内联事件。
- 提交前跑 `node --check`；改动后端后重启服务。
- 不要把 `data/.jwt-secret`、`data/users.json`、`data/backups` 提交到公开仓库。
