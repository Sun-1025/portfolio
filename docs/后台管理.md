# 后台管理

后台是 Sveltia CMS（Decap CMS 的现代替代），用来可视化编辑 `site.json`，提交到 GitHub 后由 Pages 自动发布。本文说明登录、字段、媒体、权限与排错。

## 1. 入口与登录

| 项 | 值 |
| --- | --- |
| 地址 | `https://sunzhihaoai.top/admin/` |
| 配置文件 | `admin/config.yml` |
| 挂载页 | `admin/index.html`（仅加载 CMS 脚本） |
| 登录方式 | GitHub OAuth |
| 授权代理 | `https://sunzhihao-cms-auth.netlify.app` |
| 数据仓库 | `Sun-1025/Sun-1025.github.io` |
| 分支 | `main` |

**首次登录流程**

1. 打开后台，点 `Login with GitHub`。
2. 浏览器跳到 GitHub 授权页，确认应用请求的 `repo` 权限。
3. 回调到 Netlify 代理的 `/api/callback`，换取 token 后跳回后台。
4. 左侧出现「站点内容 → 全站数据」，即可编辑。

**Token 生命周期**

GitHub OAuth App 默认签发 8 小时有效的用户令牌。过期后后台会提示重新登录，不会丢草稿（当前为简单模式，未发布的内容仍在编辑器内，刷新即丢，请先复制备份）。

## 2. 配置文件结构

```yaml
backend:
  name: github
  repo: Sun-1025/Sun-1025.github.io
  branch: main
  base_url: https://sunzhihao-cms-auth.netlify.app
  auth_endpoint: auth
  cms_label_prefix: cms/

site_url: https://sunzhihaoai.top
display_url: https://sunzhihaoai.top
locale: zh_Hans

media_folder: "assets/uploads"
public_folder: "assets/uploads"

publish_mode: simple

collections:
  - name: site
    label: 站点内容
    files:
      - name: data
        label: 全站数据
        file: site.json
        format: json
        fields: [ ... ]
```

| 键 | 作用 | 修改注意 |
| --- | --- | --- |
| `repo` | 指向内容仓库 | 换仓库时同步改，格式 `owner/name` |
| `branch` | 提交分支 | 必须是 Pages 发布分支 |
| `base_url` | OAuth 代理地址 | 换代理时改，末尾不带斜杠 |
| `auth_endpoint` | 代理内的授权路径 | 与函数路由一致，默认 `auth` |
| `media_folder` | 仓库内媒体目录 | 改了要同步 `public_folder` |
| `public_folder` | 页面访问媒体的路径 | 站点头部时用相对路径即可 |
| `publish_mode` | `simple` 或 `editorial_workflow` | 后者支持草稿/审核，需要额外分支权限 |
| `locale` | 后台语言 | `zh_Hans` 为简体中文 |

## 3. 字段说明

后台只有一个 collection：`site`，对应单文件 `site.json`。字段分组如下。

### 个人简介（`about`）

| 后台标签 | JSON 键 | 类型 | 备注 |
| --- | --- | --- | --- |
| 首句高亮 | `highlight` | 字符串 | 可含 `<em>` |
| 简介段落 | `lines` | 列表 | 一项一段 |
| 基本信息 | `facts` | 列表 | 标签 / 值 / 详情键 |
| 技术能力 | `abilities` | 列表 | 标题 / 正文 |
| 技能栈 | `skills` | 列表 | 名称 / 详情键 |
| 个人理念 | `belief` | 对象 | 段落列表 + 金句 |
| 未来方向 | `future` | 列表 | 阶段 / 说明 |

### 案例卡片（`cases`）

列表项字段：唯一键、分类、编号、标题、归属、时间、角色、摘要、标签、图片路径、外链、详情小节、结果句。

- **唯一键** 参与详情关联，新增时自己起名（如 `case-tools`），不要与现有重复，也不要修改已有项的键。
- **分类** 决定卡片落在哪条分支：实习 / 项目 / 校园 / 兴趣。
- **图片路径** 填媒体库返回的相对路径，如 `assets/uploads/demo.webp`。
- **详情小节** 是可选的，留空则详情页只显示摘要与结果句。

### 联系方式（`contacts`）

三项：类型、值、链接。链接留空则文本不可点击。

### 未来方向与站点说明（`directions`、`note`）

`directions` 用于「关于本站」页的方向列表；`note` 是站点说明段落。

## 4. 媒体管理

- 上传位置：`assets/uploads/`，与 `media_folder` 一致。
- 支持格式：图片（png/jpg/webp/gif/svg）、文档（pdf）。
- 命名建议：英文小写 + 短横线，避免中文、空格与特殊符号；WebP 优先。
- 单文件建议不超过 500 KB，超大图先压缩再传。
- 删除媒体不会自动清理正文引用，删前先全局搜索文件名。

## 5. 发布与回滚

1. 编辑完成点右上角 `Publish`。
2. CMS 通过 GitHub API 提交一个 commit，信息默认带 `cms/` 前缀。
3. Pages 检测到 `main` 更新后重建，通常 1–2 分钟。
4. 回滚：在 GitHub 提交历史找到目标版本，对 `site.json` 执行 `Revert`，或把旧内容复制回后台重新发布。

**验证是否生效**

```bash
curl -s https://sunzhihaoai.top/site.json | head -c 200
```

看返回内容里是否包含刚改的字段。

## 6. 权限管理

- 只有仓库协作者能登录后台。新增维护者：GitHub 仓库 `Settings → Collaborators → Add people`，角色选 `Write`。
- 移除维护者后，其已签发的 token 仍在有效期内可用，需在 GitHub `Settings → Applications` 里撤销授权，或重置 OAuth App 的 secret。
- OAuth App 的 `Client Secret` 只存在 Netlify 环境变量里，不要写进仓库。

## 7. 从零重建后台（换域名或换仓库）

1. 新建 GitHub OAuth App：
   - Homepage URL：站点地址
   - Authorization callback URL：`https://<代理域名>/api/callback`
2. 部署 `oauth-proxy/` 到 Netlify，配置 `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`。
3. 修改 `admin/config.yml` 的 `repo`、`base_url`、`site_url`。
4. 提交推送，打开 `/admin/` 重新登录验证。

## 8. 排错

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 点登录无反应 | 代理域名不可达或函数未部署 | 访问 `https://<代理>/auth` 应返回 302 |
| 登录后白屏 | 扩展拦截 CMS 脚本 | 无痕窗口重试，关闭拦截插件 |
| 提示 401 | token 过期或权限被撤销 | 退出重登，检查协作者权限 |
| 发布报 404 | `repo` 或 `branch` 写错 | 核对 `owner/name` 与分支名 |
| 图片 404 | 路径大小写不一致或未提交 | 检查 `assets/uploads` 下是否存在该文件 |
| 保存后线上未变 | Pages 尚未重建 | 等 2 分钟，或看 Actions 记录 |

## 9. 安全建议

- 定期轮换 OAuth App 的 `Client Secret`。
- 不在公开文档里写 token；本文提到的所有密钥都应放在平台环境变量中。
- 后台已用 `noindex,nofollow` 阻止搜索引擎收录，但地址仍可能被猜到，权限控制依赖 GitHub 账号，不依赖地址隐藏。
