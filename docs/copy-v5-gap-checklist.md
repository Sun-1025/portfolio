当前站点是「工业编辑风 + 长文叙事」，问卷要的是「极简科技 + 成长档案 + 自研工具」。视觉不需要推翻，但要收紧首页、统一事实口径、解冻核心板块。最需要先处理的不是配色，而是三件事：**技能写高了、数字没有出处、核心兴趣/经历全锁着**。

| 信息结构 | 主页 / 项目 / 工具 / 经典版 | Q99 核心三板块：实习、经历、兴趣；项目归到「经历」里 | 项目占一级导航，经典版也占一级；三板块没有独立入口 |

## 1. P0 · 先定事实口径

### 1.1 技能：把「掌握」和「在学」分开

当前 `data/site.json` 的 `skills` 列了 C/C++、Python、SQL Server、数据可视化、Git/GitHub；能力段落里 Python、Git、ESP32 都写得像常用能力。问卷 Q82 的原话是：**目前掌握 SQL Server、C 语言、C++，其他技术还有待学习。**

建议改成三组，不要删掉在学项：

- **已掌握**：C / C++、SQL Server
- **在学 / 项目里用过**：Python、ESP32、Git / GitHub、AI / Agent 工具
- **只作为项目经历出现**：数据可视化、I2C / SPI、WiFi 链路、AOS / 响应式

对应改法：

- `Python 我多半拿来做数据处理和画图` → `我在用 Python 处理数据、画曲线，还在补基础`
- `Git 我用得不花哨` → `Git 还在学，提交信息尽量写清楚改了什么`
- `C 和 C++ 是我最常用的两门语言` 可以保留，但不要延伸成「嵌入式已熟练」
- `skills` 增加 `level` 字段（`mastered` / `learning` / `used`），前端按标签区分，不要把所有词都做成同权重徽章

涉及：`data/site.json`、`public/assets/js/app.js`、`ai-server/profile.json`

### 1.2 数字和头衔：问卷没有的，先别当既成事实

提示词明确禁止编造奖项、名次、合作单位、服务人数和项目数据。当前站点有不少具体数字，先逐条核对；能核验的保留，不能核验的改成「约 / 在做 / 参与」，涉及人数的优先删。

| 3 个核心项目 | hero stats | Q84/Q93 至少列了 5 个项目 | 改为「4 个项目 / 2 个在学」或直接去掉这组统计 |

涉及：`data/site.json`、`public/classic/index.html`

### 1.3 锁卡：核心板块不能全是「暂时保密」

当前锁了 6 个案例、4 个兴趣、3 个学段。问题是：**兴趣是问卷里的核心三板块之一，校园经历也要求「尽量丰富」，全锁等于告诉访客这几块没有内容。**

- **兴趣 4 条可以先解冻。** 现有公开的「关于我」已经写过：骑行沿黄河口、羽毛球打双打补位、只玩策略类游戏、从大一开始记账。这些不是新编的事实，可以直接压成一到两句，不需要再问你。
- **校园 2 条需要你补 2–3 个具体动作。** 比如某场活动你负责什么、做了多少次、最后留下什么。没有这些，建议从「经历」主列表移出，别放 6 张空白锁卡。
- **小学 / 初中 / 高中 3 段没有内容。** 三条路：
  1. 你补每个阶段一句真实的小事，做成「从小到大」的时间线；
  2. 去掉三个学段 tab，成长线从 2025 年大学阶段开始；
  3. 继续锁，但首页不要写「从小到大」的成长叙事，否则内容和标题对不上。
- 锁卡是隐私占位，不是缺稿的补丁。公开 JSON / HTML 里的锁定正文继续保持清空，解冻时从 `private/locked-content-backup.json` 取回，不要整份回填。

涉及：`data/site.json`、`public/classic/index.html`、`public/assets/js/app.js`

### 1.4 把「个人主页」和「在线工具箱」做成案例

问卷里 Q84 说最有成就感的是本站，Q93 说最想展示的也是本站；Q37、Q100 又把工具箱当成站点的另一半。当前项目列表里没有这两个案例，这是最大的内容缺口。

建议新增两条，放在项目列表最前面：

- **`case-site` 个人主页**
  - 做了什么：独立开发 + AI 协助，从想法到上线自己推进。
  - 我负责哪一段：结构、前端、静态导出、部署、AI 助手接入。
  - 技术难点：前端、后端与 UI 交互不相容；前端用 AOS / 响应式，后端用 GitHub Pages + Gitee Pages 衔接（**只有实际部署过才写 Gitee**）。
  - 结果/边界：现在能稳定访问，留言在静态模式下走邮件回退，公开留言墙需要后端。
- **`case-toolbox` 在线工具箱**
  - 做了什么：浏览器本地处理文件，不上传服务器。
  - 我负责哪一段：工具选型、前端交互、格式转换链路。
  - 技术难点：多格式转换的边界和浏览器性能。
  - 结果/边界：5 个工具、99 条转换路径；大文件仍受浏览器内存限制。

同时调整：`work.cases`、`home.selectedIds`、`home.stats`、`work.intro`。项目卡片加两个字段：`difficulty`（一条技术难点）和 `failure`（一句踩坑/返工），对应 Q27、Q33。

### 1.5 线上 AI 仍是旧版

`ai-server` 本地已经改了联系方式和 prompt，`ai.sunzhihaoai.top` 还没重部署。当前 `ai-dock.js` 只把联系方式类问题拦到本地，其它问题仍可能拿到旧 profile 的答案。

- Q56–Q70 要的是：专业但轻松、第一人称、适中长度、能引用项目、不知道就直说、能收集访客问题。
- 当前 prompt 是「不超过 3 句话」，比 Q68 的「适中」更短；开场白「我是孙志昊的 AI 助手」也偏官方。
- 需要 Vercel 重新登录部署，或把 `/api/chat` 迁到可部署的后端；如果短期做不到，至少把客户端 fallback 扩到项目、技能、实习、学习方向，不只联系方式。
- 注意：文档第五部分是「文案 Agent 提示词」，不是访客 AI 的 system prompt。前者用来写页面文案，后者用来回答访客，不能直接整段粘贴。

涉及：`ai-server/profile.json`、`ai-server/app/api/chat/route.ts`、`public/assets/js/ai-dock.js`

## 2. P1 · 首页与信息结构

### 2.1 Hero：从「结果句」改成「身份句」

当前 H1 是「把想法做成能跑的东西」，有记忆点，但没有回答 Q81 的「你是谁、学什么、想做什么」。

建议二选一：

- **A（推荐）**：H1「正在成长的工程师」（8 字），eyebrow 用「无限进步」，副标题一句话：`山东石油化工学院物联网工程 2025 级，主攻嵌入式与 AI 应用，开放实习。`
- **B**：H1「把想法做成实物」（7 字），副标题同上，把「无限进步」放到页脚或 About 结尾。

Q 要求标签不超过 4 个，建议：`山东石油化工学院` / `物联网工程 2025 级` / `嵌入式 · AI 应用` / `东营 · 开放实习`。按钮用动词开头：`浏览项目` / `打开工具箱`。

当前 intro 是两句，建议压成一句；第二句「写代码、接传感器、跑通链路」移到 About 或项目区，不要挤在首屏。

### 2.2 导航：项目降级，三板块上来

当前：主页 / 项目 / 工具 / 经典版。

问卷 Q99 和文档第四部分都明确：核心是实习、经历、兴趣，项目作为「经历」的主体，不单独占一级导航；经典版不该和主站并列。

两个方案：

- **A（推荐，改动中等）**：首页 / 实习 / 经历 / 兴趣 / 工具；经典版移到页脚，标「2025 版存档」。
- **B（最小改动）**：保留现有三个路由，把「项目」改名为「经历」，页内加「项目 / 实习 / 校园 / 兴趣」四个筛选；经典版移到页脚。

如果不想动路由，至少先做 B 的前半段：**「项目」这个一级词换成「经历」**，否则访客会以为这里只有代码项目，看不到实习、社团和兴趣。

### 2.3 首页 About：九段长文要搬家

当前 About 有 9 段，每段 100–200 字，放在首页会把首屏之后压得很长。问卷 Q34 选「一句话即可」，文档的解释是「首页一句话，细节放内页」。

建议：

- 首屏只留一句自我介绍 + 3 个短事实（学校/方向/状态）。
- 完整 About 移到独立「关于」区或 `/about`，压到 4–5 段。
- 保留 1–2 个具体场景（比如第一次点灯、图书系统当最不讲理的用户），删掉重复的自我分析。
- 「ENTJ」可以留，但降为一条事实标签，不要占一整段。

### 2.4 增加「正在学习」

Q22、Q32 都要这个模块，当前完全没有。建议在首页项目区之前放一条 `Now`：

- `C / ESP32`：GPIO、I2C/SPI、WiFi 链路，边做边补
- `SQL Server`：索引、约束、查询优化
- `AI / Agent`：提示词、工具调用、把 AI 接进站点

每条只写「在学什么 + 现在做到哪」，不要写「已掌握」。数据结构建议加 `home.now`，渲染成 3 行，不做大卡片。

### 2.5 项目卡片：把「技术难点」提到前面

Q27 明确项目卡片里最该写技术难点，当前卡片主要写角色和结果。建议卡片统一成四句：

1. 做了什么
2. 我负责哪一段
3. 最难的一点（一条就够）
4. 结果或边界

例如语音项目：`负责 APP 端声音可视化与异常提醒；最难的是 WiFi 断线后的重连和误报阈值；最后把采样、传输、告警跑通了，误报还要继续调。`

详情页保留现有结构，但每段压到 3–5 行；在「我的核心工作」后加一小段「踩过的坑 / 返工」。

### 2.6 笔记 / 博客

Q28 选「非常希望」，当前没有。不建议一上来做完整博客系统，先加一个 `/notes` 或首页「记录」区，放 3 篇短笔记：

- 前端、后端、UI 打架时，我先拆哪一层（对应 Q85）
- 静态站的双平台衔接：GitHub Pages + Gitee Pages（确认实际部署后再写）
- ESP32 链路调试：断线、乱码、误报（从现有能力段落提炼，不编数据）
- 图书系统：交之前先当一次最不讲理的用户（已有素材）

每篇 500–800 字，标日期和标签，不写「教你」口吻。

### 2.7 工具箱：补「使用前提」

当前 5 个工具的描述基本只说「能做什么」，Q 的提示词要求每个工具再补一句「使用前提」。例如：

- 文件转换台：本地处理，不上传；大文件受浏览器内存限制。
- Markdown 转 HTML：适合短文档，复杂表格和脚本不保证还原。
- 字数统计：中英文混排按字符/词分别算。
- 单位换算 / 日期计算：只做常用范围，不替代专业计算工具。

### 2.8 开源入口

Q39 选「应该突出」。当前 GitHub/Gitee 只在页脚和个别项目链接里。建议在「经历」或「工具」区加一个「代码」块，放本站、工具箱、图书系统的仓库链接；没有公开仓库的就不放，不要用空链接凑数。

### 2.9 经典版

经典版是旧视觉，和 Q41 的「极简科技」不是一套。保留可以，但：

- 从一级导航移到页脚；
- 页面顶部标「2025 版存档」；
- 不再作为主站的门面入口。

## 3. P2 · 文案改稿

### 3.1 语气：平实、具体、少一点文学铺陈

Q91 选「偏个人博客」，Q20 选「平实真诚」，Q77 选「理性」，Q78 选「可以有一点情绪，但克制」。

当前 About 的文字质量不差，但太长、太密，有些段落像散文。建议：

- 自我介绍一句话：`我是孙志昊，山东石油化工学院物联网工程 2025 级，学嵌入式与物联网，也在做 AI 应用。`
- 「无限进步」只做一句座右铭/页脚，不要反复出现。
- 第一人称密度降下来：一段里出现 2–3 次「我」就够了，其余用「项目 / 系统 / 这次」做主语。
- 每段控制在 3–5 行；详情页长段落拆成两段，不要一段 200 字。
- 保留具体动作：点灯、调阈值、断线重连、当最不讲理的用户；删掉解释这些动作为什么重要的句子。

### 3.2 禁用词和 AI 腔

当前 JSON 里能扫到的明显项：

- `完整工程闭环`、`完整闭环`：提示词禁用「闭环」，改成「从需求到交付的完整过程」「借阅与归还流程」。
- `不是天赋型选手`（备选 Hero）：属于否定式开场，建议改成正面陈述。
- `真正学东西是在板子上`：不是禁用句，但「真正」出现频率偏高，可改「很多手感是在板子上练出来的」。

改稿后统一扫一遍：精通、顶级、神级、行业领先、颠覆、赋能、闭环、打造生态、全面提升、极致体验；以及「不是……而是……」「在这个……的时代」「真正重要的是」「答案藏在」。

### 3.3 项目文案：用四句模板

每个项目卡片按这个顺序写，详情页再展开：

1. `做了什么`：一句话说清对象和范围。
2. `我负责哪一段`：只写自己做的，不写团队整体。
3. `技术难点`：一条，具体到链路/参数/交互。
4. `结果/边界`：做成了什么，哪里还没做完。

Q33 要求写失败，详情页至少留一句「第一版哪里不对，后来怎么改」。不要写成励志故事，写清问题和动作。

### 3.4 AI 助手话术

访客 AI 和文案 Agent 分开：

- **文案 Agent**：用文档第五部分的 prompt，只负责写/改页面文案，不直接对外。
- **访客 AI**：第一人称、轻松但专业、2–4 句、引用具体项目、不确定就说不确定、不编数据。
- 开场白建议：`我是孙志昊的 AI 分身。项目、技术栈、实习安排，问我就行；不确定的我会直说。`
- 快捷问题：`本站怎么做出来的` / `你最拿得出手的项目` / `现在在学什么` / `能实习吗`。
- Q69 想收集访客问题：可以在留言框加一个「想问但没问」的可选字段，或后端只存匿名问题，不存联系方式。

## 4. P3 · 视觉微调

### 4.1 玻璃面积收一点

### 4.3 图标和控件

Q50 选「圆润柔和」，当前 `data-radius="sharp"`、`data-buttons="solid"`，整体是硬边工业风。不必把全站改圆，但可以把图标底、按钮圆角、AI fab 做得更柔和；卡片和排版继续硬边，保留「系统级界面」的稳定感。

Q44 选「动效可以丰富一点」。当前已有滚动 reveal 和玻璃 hover，建议只加两类：项目卡片进入时的轻位移、AI 面板开合的弹簧感；尊重 `prefers-reduced-motion`，不要做全屏视差。
