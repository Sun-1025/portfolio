## 三、视觉结论

- **1080P**：导航从“细窄条”变成 72px 的仪表栏，品牌、菜单、状态读数和右侧按钮形成三段式；Hero 左右两栏，右侧信号核心最大 560px，主标题两行不折行。
- **2K**：内容宽度升到 1760px，正文 18px，Hero 81.92px，板块标题 46px；没有把 1440 的版面直接放大，左右留白和字号同步扩展。
- **1440**：内容 1320px，Hero 66.24px，项目索引 300px 封面 + 正文 + 48px 箭头；首屏能看到统计条，不会只剩一个巨大标题。
- **390**：顶栏收为 62px，品牌、主题、菜单三个按钮保留；Hero 单列，标题 41.34px，两个按钮全宽；项目索引改成纵向，封面 3:2，不再挤压正文。

## 四、agent-desktop 桌面控件树复核

用 `agent-desktop` 在 1920×1080 的 Edge 窗口内读取网页控件树，确认不是“截图好看、实际点不到”：

| 控件 | 控件树实测 bounds | 判定 |
| --- | --- | --- |
| 顶栏 | 1921×73 | 72px CSS 高度，横跨全宽 |
| 主导航链接 | 65×52px（首页 / 项目 / 工具 / 经典版） | 点击区域高于 44px |
| GitHub / 主题 / 后台按钮 | 46×46 / 45×46 / 46×46 | 达到 44px |
| 首页主按钮 | 113×49 / 143×49 | 两个行动按钮都在首屏内 |
| AI 浮标 | 57×57px | 56px CSS 尺寸，可聚焦 |
| AI 面板 | 420×401px | 桌面右下方，不盖住主导航 |

复核过程：从首页进入 `#/work`，切换 dark → light，再切回 dark；用键盘 Space 打开 AI 面板，Escape 关闭；最后回到首页。导航、主题、AI 面板和路由均正常，控件树未出现横向溢出。

## 六、修复记录

- 760px 以下 eyebrow 允许换行，`SZH / 001` 不再竖排。
- 移动端 hero meta、终端行、页脚小字提升到 12–12.5px；未来方向 h3 从 11px 提到 12.5px。
- 1920 / 1440 / 390 三档 × 四条路由，叶子文本扫描均为 0 处 <12px。
- 480px 以下详情标题 30–34px，`text-wrap: wrap` 修复“监测”被单独折断。
- 移动端详情封面改为 4:3，最大高度 240–300px，不再出现 2.2:1 的窄条。
- 移动端项目索引隐藏箭头，封面与文字纵向排列，按钮全宽。
- 移动菜单背景使用 `var(--surface)`，不再透出底层页面。
- AI 面板在移动端变成底部抽屉，最大高度 82svh，输入框与快捷问题不超出屏幕。

## 七、交互回归

- 顶栏：主页 → 项目 → 工具 → 经典版，全部可达。
- 项目卡：`#/work` → `#/work/case-lib` 详情 → 返回项目。
- 主题：dark → light，刷新后保持。
- AI：浮标打开面板 → 关闭 → 再次打开。
- 移动菜单：展开 → 点击项目 → 自动收起。
- 控制台：0 个页面 JS 错误；0 个 4xx 资源。

## 八、已知限制

- 2K 屏幕下 `--wrap-max` 为 1760px，左右各留约 400px；这是刻意的阅读宽度，不是未铺满。
- Google Fonts 在受限网络下会回退到系统中文字体；回退版已截图确认不破版。
- 工具页的 99 条转换路径依赖浏览器本地能力，未做移动端性能基准。
