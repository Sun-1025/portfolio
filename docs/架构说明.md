# 架构说明

## 1. 总体结构

```
浏览器
  │
  ├─ 前台 SPA（public/index.html + app.js）
  │    ├─ #/            个人主页
  │    ├─ #/work        项目列表 / 详情
  │    └─ #/tools       工具列表 / 详情
  │
  ├─ 经典版（public/classic/index.html，独立静态页）
  │
  └─ 后台（public/admin/index.html + admin.js）
       │
       └─ Express API
            ├─ /api/auth        登录 / 退出 / 会话 / 改密
            ├─ /api/content     读内容 / 保存内容 / 备份恢复
            ├─ /api/admin       图片上传 / 媒体库
            └─ /api/events      SSE 内容更新
                 │
                 └─ data/site.json（唯一内容源）
```

## 2. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 服务 | Node 18+ / Express 4 | 轻量、单进程、局域网部署简单 |
| 鉴权 | JWT + HttpOnly Cookie | 前端读不到 Token；适合单管理员 |
| 内容库 | JSON 文件 | 无需数据库；备份/迁移/版本控制直观 |
| 实时刷新 | SSE | 比 WebSocket 轻；后台保存后前台自动刷新 |
| 上传 | multer + 白名单 | 8MB 上限；排除 SVG 降低 XSS 风险 |
| 静态导出 | 自写脚本 + sharp/terser/clean-css | 输出可直接丢 GitHub Pages / Cloudflare |
| 前台 | 原生 JS + 原生 CSS | 页面少，避免框架与 Tailwind 运行时开销 |
| 管理 UI | 原生 JS 表单 | 单管理员、字段化编辑，够用且轻 |

## 3. 模块边界

- `src/store.js`：只负责读写 JSON、备份、用户；不关心 HTTP。
- `src/auth.js`：只负责签名、校验、Cookie、限流、会话过期；不关心页面。
- `src/routes/*`：HTTP 层，参数校验 + 调用 store/auth。
- `public/assets/js/app.js`：路由 + 渲染 + 主题 + SSE；不直接读写文件。
- `public/assets/js/admin.js`：后台表单 + 保存 + 媒体 + 备份；不直接改 JSON 文件。
- `public/tools/*.js`：独立工具模块，导出 `render(root, ctx)`；由 `app.js` 动态 import。

## 4. 数据流

### 保存

```
后台表单修改
  → state.content（内存）
  → PUT /api/content
  → src/routes/content.js 校验必要字段
  → store.writeContent()（原子写 + 自动备份）
  → SSE 广播 content
  → 前台重新拉取 /api/content 并重渲染
```

### 静态发布

```
data/site.json
  → scripts/export-static.js
  → dist/（无后台、无 API）
  → GitHub Pages / Cloudflare Pages
```

静态版前台请求 `/api/content` 失败时，自动回退到 `/data/site.json`；SSE 自动跳过。

## 5. 分支与路由

`branches` 是分支元数据，`nav` 是导航入口。两者独立：

- `nav.visible`：入口是否显示。
- `branches.visible`：SPA 路由是否允许访问。
- `classic` 是独立静态页，不经过 SPA 路由；隐藏时需在页面/反向代理层处理。

## 6. 安全边界

- JWT 签名密钥自动生成到 `data/.jwt-secret`，不要提交。
- 管理员密码 bcrypt 哈希，登录失败限流。
- 上传只允许位图格式，排除 SVG。
- 所有用户内容输出走 `esc()` 转义；外链走 `safeUrl()` 白名单。
- 建议后台只在局域网 / Tailscale 访问；公网必须加 HTTPS 与访问控制。

## 7. 已知边界

- JSON 文件适合单管理员、小规模内容；多人并发写入需要换数据库或加锁。
- SSE 在 Nginx 反代时必须关闭 `proxy_buffering`。
- 后台是桌面优先布局，移动端只保证可打开，不保证完整编辑体验。
- 静态导出不会包含后台与 API；外网内容更新需要重新导出。
