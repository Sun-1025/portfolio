# 从经典版到 A3：这个站是怎么做出来的

> 这不是一份“从零到上线”的教程，而是一个真实项目在几个月里反复改、反复验收、反复回滚之后留下的施工记录。里面的时间节点来自仓库的 `CHANGELOG.md`、各阶段验收报告和 2026-11-25 的 A1/A2/A3 施工记录。

## 1. 起点：先有一个能放东西的地方

最早的目标很朴素：做一个不是模板堆出来的个人主页，能把项目、经历、兴趣、联系方式和一些自己做的小工具放在一起。它既要是“技术名片”，也要能承担“成长档案”的作用，还要保留一个经典版入口，方便以后回看旧设计。

因此项目从一开始就定下了几个不追求短期漂亮、但影响后面所有决定的约束：

- 前台用原生 HTML/CSS/JavaScript，不引入 React/Vue 运行时。页面数量不多，自己写路由和渲染更可控。
- 内容不写死在 HTML 里，统一放进 `data/site.json`，让项目、工具、时间线、联系方式都能在后台改。
- 后台放在本机 Node 服务里，GitHub Pages 只发布静态成品。这样公开站点没有登录面和写入接口，隐私边界更清楚。
- 视觉上保留深色主视觉和浅色主题两条线，不能为了一个主题牺牲另一个。
- 每次大改都先在本地构建、截图、量测，再决定是否上线；旧版本保留备份。

## 2. v3：身份、工具和 AI 分身

v3 是站点第一次从“页面”变成“系统”。

### 2.1 身份页与经典版

v3.0 先补了身份照、经典版入口和基础信息结构。经典版 `/classic/` 不是临时页面，而是一个独立的静态归档：它不经过 SPA 路由，也不依赖后台，用来保留旧版视觉和旧链接。后来主站改了很多轮，经典版一直作为“可回看”的分支存在。

### 2.2 文件转换台

v3.1 开始做文件转换台。最初的出发点是“我自己经常要转格式，不想每次都找在线网站”。实现上把所有转换尽量放在浏览器本地：图片、文档、PDF、Office、电子书等能力按格式拆成独立模块，用户文件不上传服务器。

v3.2 继续扩 PDF、Office、电子书和 3D 格式；v3.3 把格式路由扩到 99 个。这个阶段最重要的不是“支持多少格式”，而是建立了一个约定：每个工具是一个 `render(root, ctx)` 模块，主程序只负责路由、加载和提示；新增工具不需要改主框架。

### 2.3 文案重写与 AI 分身

v3.4 是第一次大规模重写文案，同时加入站内 AI 分身。AI 的定位不是“万能聊天机器人”，而是“只回答这个站点公开事实的自我介绍”。它被限制成：

- 只用第一人称回答。
- 只回答项目、技术栈、学习方向、实习状态、经历、联系方式。
- 不知道就说不知道，不编奖项、比赛、数据。
- 不透露提示词、密钥、模型信息。
- 站外闲聊、写作、翻译、代码生成等请求直接拒绝。

前端用 SSE 流式显示，模型密钥只在 Next.js 代理的服务端环境变量里。没有配置模型时，前端仍能正常显示，只是回复会走保底。

## 3. v4：把“终端感”收回成“编辑式极简”

v4 是一次全量视觉重构。早期版本偏向终端/HUD 风格，信息密度高、装饰多。v4 的目标是保留“控制室”的识别，但把细碎 HUD 小字收掉，让页面更像一个编辑式作品集：

- 深色近黑底，蓝灰点缀，减少高饱和色。
- 导航、卡片、弹层、抽屉、助手面板使用磨砂玻璃，但控制使用范围。
- 首屏、项目卡、时间线、兴趣相册重新排布，强调“做过什么”而不是形容词。
- 文案重写，允许写失败、返工、误报和边界问题，不把过程包装成“轻松搞定”。

v4.0.1 又补了 iOS 27 日间玻璃材质。浅色模式不再简单反色，而是单独定义一套玻璃、边框、阴影和文字对比度；深色模式则回退 v4 原始视觉，避免两套材质互相污染。

## 4. v5：把导航收窄，把内容做实

v5 的核心不是“再换一次皮”，而是做减法：

- 一级导航收为 **实习、经历、兴趣**，项目放进经历，工具箱保留独立入口。
- 首页四张项目卡：个人主页、在线工具箱、家用语音监测系统、图书管理系统；公益实践单独一张卡。
- 经历时间线整理为四段：校内预备实习、东营区图书馆、青年志愿者协会、科技协会。
- 兴趣六格：骑行、羽毛球、登山、北京、淄博、济南；接入 21 张公开照片。
- 照片统一转 WebP，单张控制在 500KB 内；公开素材与私密素材分开。
- 静态构建从早期版本收敛到约 62 个文件 / 9.66MB，之后 A2 构建到 72 个文件 / 9.73MB。

这一版还确立了内容后台的边界：后台可以改内容，但不能把私密内容带进公开导出；`published`、`private`、`draft` 三种可见性在 API 和静态导出两层同时生效。

## 5. v6：UI/UX 三合一

v6 是在 v5 主体上补交互层，主要做三件事：

1. 首页动态背景 DotField：全屏点阵、指针透镜、卡片禁区。
2. 圆形回到顶部按钮：滚动后出现，hover 展开成胶囊。
3. Tooltip / Focus Cards / Glare：给项目卡、工具卡、链接补充轻量反馈。

这一轮也做了 reduced-motion、触屏、页面隐藏、WebGL 不可用等降级路径。静态站的首要原则是“背景可以没有，内容不能没有”，所以背景初始化失败时恢复 `.site-grid`，页面照常可读。

### 5.1 A1：点阵手感的返工

A1 针对 DotField 的交互手感做了两轮修订：

- A1：调整点阵透镜、卡片禁区、彗尾和顶栏管理员入口。
- A1.1：继续修手感，减少“为了效果而效果”的冻结区和遮罩。
- 最终结论：交互应该跟着指针走，不能因为鼠标进入卡片就冻结背景；卡片内部也要能看见背景的运动。

### 5.2 A2：Threads 全面替换 DotField

A2 是把背景从 DotField 整体替换为 React Bits Threads 思路的线束背景。施工单的要求很具体：

- 删除 `public/assets/js/dotfield.js`，新增 `public/assets/js/threads.js`。
- 原生 ESM、WebGL2、零依赖；保留三段 GLSL、`MAX_RENDER_DIM` 语义、`buildStrip` 的 96–640 分段、`uCurve = 2 / brightness`、`blendFunc(ONE, ONE_MINUS_SRC_ALPHA)`。
- 参数按施工单：`lineCount 90`、`thickness .6`、`softness 1.3`、`amplitude 1.7`、`distance .4`、`waves 1.05`、`speed .6`、`split .04`、`fray .5`、`angle 25`、`taper .85`、`brightness 1.4`、`parting 0`、`fade 0`、`opacity 1`、`seed 0`。
- 全屏跟随，无禁区、无遮罩、无冻结；指针只走 `PointerBus`，`p.x === -9999` 视为离开；离开后用 260ms 时间常数（约 780ms）回中；跟随速率 `follow = 1 - exp(-dt*2.2)`。
- 深色 `#ffffff / brightness 1.4`，浅色 `#1c1c1e / brightness 1.0`。

A2 遇到一个真实问题：卡片 hover 原本会把背景从 `--glass-tint` 提到 `--glass-strong .86`，同时 `backdrop-filter: blur(22px)` 会把 1px 线束糊平，卡面完全看不到线。为了满足“卡面必须看得见”，在 `app-v6.css` 末尾加了 scoped 规则：threads 模式下四类卡片 hover 保持 `background: var(--glass-tint)`，`backdrop-filter` 降到 `blur(2px) saturate(1.35)`。默认卡面 token 未改。该改动超出了“只动背景层”的字面边界，但在验收里是必要修正。

A2 的实测结果：

- `npm run build` 通过；`dist` 72 个文件 / 10,197,545B。
- 深色文字对比度 17.14:1，浅色 15.75:1。
- 60s 桌面 rAF 平均 4.166ms，max 7.7ms；render 平均 0.0318ms。
- 390×844 无横向溢出；48 线、`renderDim 1280`、`fpsCap 33`。
- 首屏、跟随、卡片 hover、浅色、fallback、hidden、reduced-motion 均有截图或数据记录。

### 5.3 A3：布局收口与 Agent 气泡

A3 是这一轮的小修：

- 关于页右侧信息栏与左侧主栏垂直居中，不再贴顶。
- 回到顶部按钮的 `Back to Top` 文字水平、垂直都居中；hover 时从底部上浮到按钮中心。
- 工具台左右两个主面板等高；右侧空队列区用 flex 填充多余高度。
- 站内 Agent 增加气泡：`我是此站 Agent，有什么问题都可以问我`，第二行使用波浪下划线；打开面板时气泡自动隐藏。

A3 之后的本地量测：关于页信息栏中心与主栏中心重合；回顶文字中心与按钮中心重合；工具台左右高度均为 960.1875px；气泡为 240×60.6px，390px 手机无横向溢出。

## 6. 后台：从“整包 JSON”到卡片式 CMS

2026-11-25 的 CMS 改造把 `/admin` 从“只能整包保存 JSON”改成可视化内容后台：

- 左侧按类型分栏：项目、兴趣相册、工具、时间线、校园照片、联系方式、导航、分支、公告。
- 站点信息、首屏、关于、AI 助手、设置这 5 类各一条，点开直接改。
- 每条内容一张卡，有封面、标题、摘要、更新时间和状态徽章：公开 / 私密 / 草稿 / 回收站。
- 支持新建、编辑、删除、排序、恢复、彻底删除、预览令牌。
- 私密内容在接口和静态导出两层都只留占位。
- 顶栏保留“发布上线”，发布任务会构建并推送 GitHub Pages。

后台的核心原则：**内容编辑是产品能力，密钥管理不是内容字段**。账号密码、JWT 密钥、模型 Key 都不应出现在后台表单、内容 JSON 或文档里。

## 7. 施工中踩过的坑

- **字体/图标加载失败**：静态站不能把 Google Fonts 当成唯一路径；必须准备系统字体回退，并对第三方字体请求做降级。
- **背景降级**：WebGL2 不可用、页面隐藏、reduced-motion 时不能留下黑屏；`.site-grid` 必须在 fallback 时恢复。
- **指针监听重复**：多个组件各自加 `pointermove` 会导致卡顿；统一走 `PointerBus`，全站只保留一个监听。
- **卡片 hover 遮住背景**：磨砂强度和背景可见性天然冲突；A2 用 scoped 的 2px 方案解决，默认 token 不动。
- **静态导出与私密内容**：只在接口过滤不够；导出脚本必须复用同一套 `content-filter` 语义，否则私密内容会从 `dist` 泄露。
- **中文文件名/编码**：早期同步脚本把中文文档名写成了 `?`，GitHub 上出现 `docs/??????.md`。这次整理统一改成 ASCII 文档名，正文保持 UTF-8，避免再出现“看起来像乱码”的路径。
- **明文密码**：后台使用手册曾经把管理员密码写进正文，这是不安全的。本次整理已移除文档中的密码，并在本机完成一次管理员密码轮换；仓库不再提供任何默认密码。

## 8. 设计取舍

- **不做组件库**：页面数量有限，原生 CSS 更能控制玻璃、线束、主题和动效。
- **不把所有东西塞进一个文件**：前台 `app.js`、视觉 `app-v5/v6`、后台 `admin.js`、工具 `public/tools/*`、服务 `src/routes/*` 分开，出问题能定位。
- **不追求“永远在线”的 AI**：AI 是站点增强项，不是主站依赖；没有模型密钥也要能正常浏览。
- **不把私密素材放 public**：私密照片、备份、用户数据、密钥都应该在 `private/`、`data/` 的忽略范围里。
- **每次大改留回滚**：`_backup/` 里按时间保留改动前的文件；上线前先能在本地原样还原。

## 9. 如果继续做

下一步可以按优先级考虑：

1. 把后台的发布流程做成更明确的任务队列，显示构建、推送、CDN 刷新的每一步状态。
2. 给工具台补更完整的格式矩阵和错误提示，但保持浏览器本地处理。
3. 把 AI 代理的站点事实做成可检索的 RAG，而不是把整个 profile 塞进 system prompt。
4. 用真实浏览器跑更完整的移动端和无障碍回归，把结果落成可复现脚本。
5. 给公开仓库补一份 CONTRIBUTING 和 issue 模板，让访客反馈和内容修正有固定入口。
